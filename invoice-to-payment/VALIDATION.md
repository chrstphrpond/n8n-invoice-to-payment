## What answers for what

n8n, its Webhook (with `rawBody`), Code, If, Switch, HTTP Request (JSON, binary upload, file download) and Respond to Webhook nodes, its retries, error outputs and error-workflow mechanism are real. Every service the workflows call is a **local stand-in** in the test process (`standins/`, `_shared/lib/`):

- the CRIT data service: config, ledger, rows, dead letters (kit), plus the invoice-number sequence and the compare-and-set update (`standins/billing-data.mjs`), with unique keys and Idempotency-Key replay
- a document rendering service: takes the HTML and returns a valid one-page PDF with the document's text, the same bytes for the same HTML. It does not lay out the HTML, so the look of the template was not rendered to PDF
- object storage: PUT and GET of the PDF, with its SHA-256
- a transactional email API in Resend's `POST /emails` request shape, honoring Idempotency-Key with a replay of the first answer
- the payment processor's refund call, honoring Idempotency-Key
- Slack `chat.postMessage` for `#crit-alerts` (the error workflow) and `#crit-billing` (review and watchdog)

No model is called anywhere in this set. The clients and every address are test records (`fixtures/clients.json`, `.example` domain). Rows seeded straight into the data service for the payment, change and sweep scenarios get the kit's control id format (`invoices_5`); rows the workflows write get the service's own (`invoice_0004`).

## Validator warnings accepted

The runtime profile has no warnings. The strict profile reports warnings, no errors. None is a defect:

- **"Code nodes can throw errors"** (20 issue, 15 payments, 17 chase, 3 error workflow): deliberate. A Code node throws when an answer cannot be trusted (an unknown ledger outcome, a row without an id, a PDF whose hash does not match, a missing config key); the run then fails into the error workflow instead of guessing.
- **"Invalid $ usage detected"** (17, 11, 6, 2): the kit's `ctxFrom($, names)` passes n8n's `$` to a helper that calls `$(name)` for each candidate node. It works in n8n (every e2e scenario uses it); the static check does not follow the call.
- **"DateTime is from Luxon library"** (11, 4, 11): triggered by `Intl.DateTimeFormat` in the inlined date helpers. No Luxon is used.
- **"Use $helpers not helpers"** (1 per workflow with a signed webhook): the signature check reads the raw body with `this.helpers.getBinaryDataBuffer`, n8n's Code-node call for binary data, passed to a helper. It works in every e2e scenario.
- **"Webhooks should always send a response, even on error"** (1 per workflow): the suggestion is `onError: continueRegularOutput` on the Webhook node. Every path already ends in a Respond to Webhook node (the lint checks it); a failure before the answer makes n8n answer 500, which is what should make the sender retry.

## Not verified

- **No real vendor.** The data service, renderer, storage, email API, payment processor and Slack are stand-ins. The requests follow the public shapes (Resend's send-email body, a bearer-token object store, a Stripe-like refund call) but were never sent to a real service. Real S3 or R2 needs SigV4 signing, which these nodes do not do.
- **The template's look.** The HTML is unit tested for content and escaping; no real renderer turned it into a PDF in this run.
- **The Schedule Triggers.** `INVOICE_SCHEDULES=off` in the e2e run; the sweeps were started by signed requests. The schedule settings are checked by a unit test, not by n8n firing them.
- **Concurrency against a database.** The races were real parallel requests through n8n, but the data service stand-in is in memory and answers one request at a time, so its guarded writes are atomic by construction. The Postgres statements for the sequence, the compare-and-set update and the guarded writes are in SPEC.md, not run against Postgres.
- **Real key expiry.** No stand-in expires an Idempotency-Key; the 23-hour window was tested with seeded timestamps.
- `saveDataSuccessExecution: none` is set, but this run did not inspect n8n's execution table to confirm what it keeps.
